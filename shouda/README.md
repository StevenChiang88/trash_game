# 純手打 Code

AI 都會寫程式了，你還在手打？穿格子襯衫的軟體工程師上台，把寫程式當成傳統技藝現場表演：一首歌一支程式，跟著節奏一個字母一個字母打出來。不用會寫程式，看字母按鍵盤就好。

## 怎麼玩

寫著字母的音符從右邊飛過來，**飛進左邊圈圈的那一刻，按同一個字母的鍵**。打中一顆，螢幕上的程式就多長出一段。

| 操作 | 手機 | 電腦 |
| --- | --- | --- |
| 打音符 | 點下面寫著字母的鍵 | 直接按鍵盤上的那個字母 |
| 執行程式 | 歌唱完後點「▶ Run」 | Enter／空白鍵 |
| 暫停 | 右上角的暫停鈕 | Esc |

同一根手指負責的鍵顏色一樣（音符下緣也有同一個顏色），找起來比較快。

## 判定

| 和音符進圈的時間差 | 判定 | 觀眾熱度 |
| --- | --- | --- |
| 0.07 秒內 | 完美 | +3 |
| 0.14 秒內 | 不錯 | +2 |
| 0.2 秒內 | 勉強 | +0.8 |
| 超過還沒按 | 漏掉 | −10 |
| 音符在圈裡卻按了別的字母 | 按錯 | −10 |

- 連擊越多，打中加的熱度多一點（最多再加 1）。
- 太早按（離音符進圈還超過 0.2 秒）不算數，也不扣分。
- 漏掉的那一段程式會變成紅色的錯字，Run 的時候會跳出「有幾個錯字」。
- 第 2 場起觀眾會越來越不耐煩：熱度每秒掉 0.3 ×（第幾場 − 1），最多每秒 4；第 16 場以後每場再多 0.25。
- **熱度掉到 0，觀眾走光，這次巡演就結束。** 歌唱完熱度還在，就按 Run，程式跑出結果，觀眾丟紅包、銅板。

## 一場一場變難

每一場一首歌。先數四拍（木魚），然後音符一顆一顆來，大多一拍一顆，偶爾半拍、偶爾空一拍。

| 第幾場 | 鍵 |
| --- | --- |
| 1–2 | D F J K |
| 3–4 | S D F J K L |
| 5–7 | 兩排：E R U I／D F J K |
| 8 起 | 兩排：E R U I／S D F J K L |

- 歌每場快 6 拍／分，第 16 場以後每場再快 3 拍／分；半拍的音符越來越多，音符從 27 顆左右慢慢加到 70 顆。所以再厲害也會有撐不下去的一場。
- 每種語言是一首不一樣的歌：

| 語言 | 難度 | 歌 | 打賞倍率 |
| --- | --- | --- | --- |
| Python | ★ | 慢歌（92 拍／分起），適合暖身 | ×1 |
| JavaScript | ★★ | 節奏忽快忽慢，半拍多、空拍也多 | ×1.15 |
| C | ★★ | 穩穩的四拍，幾乎不休息 | ×1.2 |
| Java | ★★ | 一首很長的歌（音符多三成） | ×1.25 |
| Rust | ★★★ | 又快又密（112 拍／分起，半拍最多） | ×1.5 |

螢幕上長出來的程式是那種語言真的寫得出來、跑得動的小程式，每場換一支；Run 之後顯示的輸出就是它真的執行的結果。

選語言的地方還有一個 HTML。選了會發生什麼事，自己試試看。

## 十三行博物館特別演出

每 4 場（第 4、8、12…場）是十三行博物館的特別演出：

- 歌是出土的古老語言，輪流是 BASIC、FORTRAN、COBOL、組合語言。
- **音符上的字母被土蓋住**，要飛到離圈圈 0.45 秒以內才看得到。
- 這一場的打賞加倍。

## 干擾

| 從第幾場 | 干擾 | 怎麼處理 |
| --- | --- | --- |
| 2 | 小朋友衝上台 | 在他走到桌子前點他。沒攔到，他會把鍵帽拔起來亂插，鍵的位置打亂 6 秒（上面寫的字母還是對的） |
| 3 | 阿嬤擋在鍵盤前面問問題 | 點她的對話框回答，不然鍵盤按不到 |
| 5 | PM 打電話來 | 點「掛掉」。響著的時候熱度每秒多掉 2.5，放著不管響 5 秒後再扣 8 |

十三行的特別演出只有校外教學的小朋友會衝上台。

熱度很低（35 以下）的時候，鍵盤上面會冒出一條會發光的按鈕。

## 打賞和裝備

謝幕時觀眾打賞，算法是（打中幾顆 × 5 ＋ 完美幾顆 × 2 ＋ 最大連擊 × 4 ＋ 謝幕時的熱度 ＋ 20 × 第幾場）×（打中的比例）² × 語言的打賞倍率，十三行再 ×2。

打賞會一直存著，在封面、謝幕和結算畫面可以買裝備，買了就一直有：

| 裝備 | 效果 | 價錢 |
| --- | --- | --- |
| 咖啡 | 漏掉扣的熱度每級少 12%（最多 3 級） | 800／1,800／3,000 |
| 機械鍵盤 | 判定時間每級寬 8%（最多 3 級） | 600／1,500／2,500 |
| 親友團 | 開場熱度每級多 8（最多 3 級） | 900／2,000／3,200 |
| 自動補括號 | 每首歌的音符少 12% | 2,500 |

| 撐過幾場 | 封號 |
| --- | --- |
| 0 | 台下的觀眾都比你會打 |
| 1 | 實習生 |
| 3 | 資深工程師 |
| 6 | 技術長 |
| 10 | 手打 code 傳人 |

## 平衡

難度只用模擬的玩家跑過，還沒有真人試玩的數據。模擬的玩家時間抓得準不準（誤差）、按錯鍵的機率（鍵越多越容易按錯）、換一顆不同的鍵要多久都不一樣；遇到干擾會晚一下才處理；不會按那條發光的按鈕。

| 模擬的玩家 | 裝備 | 語言 | 撐過幾場（中位數） | 一次巡演多久 |
| --- | --- | --- | --- | --- |
| 新手（誤差約 ±0.085 秒、6% 按錯） | 沒有 | Python | 7 | 約 3.5 分鐘 |
| 新手 | 沒有 | Rust | 5 | 約 2 分鐘 |
| 新手 | 全買 | Python | 12 | 約 5 分鐘 |
| 普通（±0.06 秒、3.5% 按錯） | 沒有 | Python | 11 | 約 5.5 分鐘 |
| 普通 | 沒有 | Rust | 10 | 約 4 分鐘 |
| 普通 | 全買 | Python | 24 | 約 10 分鐘 |
| 熟手（±0.04 秒、1.5% 按錯） | 沒有 | Python | 17 | 約 8 分鐘 |

普通的玩家一次巡演大約拿 6,000 元打賞，裝備全部買齊總共 18,800 元，大約要三、四次巡演。

連續玩 30 分鐘（75 場）量過記憶體：網頁用的記憶體一直在 1.3～1.6 MB，畫面上的元素數量也沒有增加。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 遊戲本體，單一檔案，沒有建置步驟；戲台和音符用 canvas 畫，音效用 Web Audio 合成，題庫（每種語言的小程式和它的輸出）寫在頁面裡的 `<script type="text/plain" id="progs">` |
| `og.png` | 貼到脆、LINE 時的預覽圖（1200×630） |
| `favicon.svg`、`apple-touch-icon.png` | 分頁圖示、加到主畫面的圖示 |

存在瀏覽器裡的資料：`sd.best`（最多撐過幾場）、`sd.bank`（存了多少打賞）、`sd.up`（買了哪些裝備）、`sd.lang`（上次選的語言）、`sd.html`、`sd.ai`（兩個小紀錄）、`sd.mute`（靜音）。

要調數值：

- 判定時間：`W`；熱度加減：`HEAT0`、`H_GAIN`、`H_MISS`、`H_COMBO`；觀眾不耐煩：`DRAIN_N`、`DRAIN_MAX`。
- 每一場怎麼變難（鍵、速度、半拍、音符數、干擾頻率）：`showOf`；每組鍵：`KEYSETS`；每種語言的歌：`SONG`。
- 干擾：`PHONE_DRAIN`、`PHONE_T`、`PHONE_PEN`、`KID_T`、`KID_MIX`；十三行的土：`DIRT_T`；幾場一次特別演出：`SHL_EVERY`。
- 裝備：`UPG`；封號：`RANKS`。
- 題庫：頁面裡的 `progs` 區塊。格式是「`@@ 代號|名稱|難度星數|打賞倍率|一句介紹`」開始一種語言，程式之間用 `---`，程式和它的輸出之間用 `>>>`。
